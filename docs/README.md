# revive website

Hugo source for <https://revive.run/> — the proof of concept from
[issue #1647](https://github.com/mgechev/revive/issues/1647), replacing the
retired Gatsby site with a [Hugo](https://gohugo.io/) +
[Hextra](https://github.com/imfing/hextra) setup (the same stack golangci-lint
uses). The site is generated from the documentation that already lives in this
repository, so docs are maintained in one place only.

## Prerequisites

- [Go](https://go.dev/) (the theme is a Hugo Module, fetched via Go)
- [Hugo **extended**](https://gohugo.io/installation/) >= 0.148

## Build locally

From the repository root:

```sh
go run ./scripts/website # generate content from README.md and RULES_DESCRIPTIONS.md
hugo -s docs server      # serve at http://localhost:1313/
```

For a production build: `hugo -s docs --gc --minify` (output in `docs/public/`).

## Layout

Hand-written (committed):

- `hugo.yaml`, `go.mod`, `go.sum` — site and theme (Hextra module) configuration
- `content/_index.md` — homepage
- `static/sw.js` — self-destroying service worker (see below)

Generated by `go run ./scripts/website` (git-ignored, see `.gitignore`):

- `content/docs/` — the docs page, derived from the repository `README.md`
- `content/r/` — the single rules page (`/r/`, all rules with `#<rule-name>`
  anchors), derived from `RULES_DESCRIPTIONS.md` and cross-checked against
  `config.AllRules()`
- `static/images/` — images copied from `assets/`

## Deploy notes

- **GitHub Pages** — built and published by `.github/workflows/docs.yaml`.
  The deploy job stays skipped until a maintainer enables GitHub Pages
  (source: GitHub Actions) on this repository and sets the `WEBSITE_DEPLOY`
  repository variable to `true`; the build job runs and validates the site on
  every PR regardless.
- **DNS / CNAME** — pointing revive.run at GitHub Pages is a maintainer
  action and is pending.
- **Service worker** — the old Gatsby site registered a service worker at
  `/sw.js`, so returning visitors would otherwise keep seeing the cached old
  site forever. `static/sw.js` is served at the same scope and unregisters
  itself, then reloads open tabs (the standard self-destroying-service-worker
  pattern). Keep it deployed indefinitely.
- **Legacy URLs** — old links of the form `/r#<rule>` and `/r/#<rule>`
  (including the ones every released revive binary prints) keep working
  natively: all rules live on the single `/r/` page and its heading anchors
  use the same GitHub-style slugs as the old site.
